# DUP-004 — Implement a dedicated VRDB collision-null engine per analysis slice

**Priority:** P0  
**Status:** Planned  
**Depends on:** DUP-002, DUP-003

## Goal
Add a new null-model layer that answers one specific question:

> Given a slice of size N and a VRDB-derived name distribution, how many duplicate name-string collisions should occur by chance?

## Scope
For each slice (full hearing, bucket, position slice, time slice, geography slice, etc.), compute:
- observed duplicate pairs
- observed number of unique names
- observed max repeat count for a single normalized name
- expected duplicate pairs under the selected VRDB baseline
- expected count per specific name where needed
- Monte Carlo reference bands and tail probabilities

Minimum required metric:
- `expected_pairs = C(N_slice, 2) * Σ p_i^2`

Monte Carlo outputs should include, at minimum:
- mean/median expected pairs
- p95 and p99
- tail probability for observed pairs
- optional max-repeat reference bands if stable enough

## Design rules
- Compute each slice with that slice’s own `N_slice`.
- Do **not** linearly allocate a global duplicate expectation down into buckets.
- Treat outputs strictly as **string-collision** expectations, not person-duplication estimates.

## Failure modes and mitigations
- **Failure mode:** slice-level expectations are derived by rescaling a hearing-wide result.  
  **Mitigation:** each slice must run the null independently with its own N and baseline variant.
- **Failure mode:** small buckets create highly discrete, unstable tail behavior.  
  **Mitigation:** low-power/descriptive-only gating and explicit Monte Carlo precision metadata.
- **Failure mode:** “max repeated name” is interpreted too literally in sparse slices.  
  **Mitigation:** mark it secondary/descriptive unless calibrated.

## Acceptance criteria
- Per-slice expectations are computed directly from slice N and selected VRDB probabilities.
- The engine produces additive outputs without modifying existing detectors.
- All outputs are labeled as VRDB-derived collision-null metrics.

## Verification
- Closed-form toy-case tests for expected pairs.
- Simulation parity tests against direct multinomial draws from known probability vectors.
- Regression tests showing that bucket expectations are not derived from a linearly rescaled global expectation.
