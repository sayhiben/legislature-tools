# DUP-008 — Make `hearing_empirical` and degraded baselines descriptive-only; remove fake null outputs

**Priority:** P0  
**Status:** Completed (2026-02-28)  
**Depends on:** DUP-001

## Goal
Prevent statistically invalid inference when the requested baseline is self-referential or has degraded into a fallback that cannot support proper uncertainty statements.

## Problem
A same-hearing empirical baseline is circular for anomaly detection: it uses the hearing to define the null for the hearing itself. In addition, “not computed” must not appear as `p=1` or `z=0`, because that reads like evidence for the null instead of unavailable inference.

## Scope
When baseline mode is self-referential or degraded:
- set `inferential_status = descriptive_only` or `unavailable`
- set inferential fields to `NA`
- propagate explicit reason codes
- preserve DUP-001 statistical-contract disclosures in payload/UI (do not hide baseline/status callouts)

Apply to:
- `hearing_empirical`
- registry-requested baselines that degrade to empirical
- any analytic-only/no-samples path that currently emits fake-null defaults

## Failure modes and mitigations
- **Failure mode:** fallback outputs look like ordinary inferential outputs.  
  **Mitigation:** status field, reason code, hidden p-values, hidden significance flags.
- **Failure mode:** downstream code treats `NA` as zero or false.  
  **Mitigation:** schema tests and frontend handling tests.

## Acceptance criteria
- No self-referential baseline emits p/q/z as if meaningful.
- No skipped inference path emits `p=1` or `z=0`.
- Reports visibly mark descriptive-only states.
- Baseline and inferential-status declarations remain visible on duplicate charts/tables even when inferential fields are `NA`.
