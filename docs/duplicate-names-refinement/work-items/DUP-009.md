# DUP-009 — Preserve scope semantics; remove silent fallbacks that change the estimand

**Priority:** P0  
**Status:** Planned

## Goal
Ensure that `full_hearing`, `matched_only`, and `unmatched_only` mean exactly what they say, or are marked unavailable.

## Problem
A scope that silently becomes some other scope is not a valid analysis target. If required match-assignment inputs are missing, or inference filters empty the frame, the correct behavior is “unavailable,” not substitution.

## Scope
- Disable `matched_only` and `unmatched_only` when match assignments are missing or malformed.
- If non-person exclusion empties the inference frame, mark the relevant scope unavailable.
- Add explicit `scope_status` and `scope_reason` fields.
- Keep `inferential_status`/`inferential_reason` from DUP-008 as separate fields; do not overload them for scope availability semantics.

## Failure modes and mitigations
- **Failure mode:** engineers preserve execution by copying `full_hearing` into `matched_only`.  
  **Mitigation:** hard guardrails and regression tests against aliasing.
- **Failure mode:** UI still offers unavailable scopes.  
  **Mitigation:** disable or hide with explanation tooltip.

## Acceptance criteria
- No scope silently aliases another scope.
- Unavailable scopes emit status/reason and no inferential metrics.
- UI and exports reflect actual scope availability.

## Verification
- Unit tests for missing assignments and empty filtered frames.
- Frontend integration tests for disabled scopes.
- Regression tests ensuring no fallback copies appear.
