# DUP-012 — Repair the Pro vs Con position concentration method

**Priority:** P1  
**Status:** Done (2026-02-28)

## Goal
Make the position concentration analysis statistically valid and clearly bounded in meaning.

## Problem
A one-sided permutation p-value is only valid if direction was specified before looking at the data. Cluster-induced dependence also makes naive Bernoulli/bootstrap intervals too optimistic.

## Scope
- Replace sign-adaptive one-sided testing with:
  - a two-sided permutation test on `|effect|`, or
  - a pre-specified one-sided direction fixed in config
- Replace naive bootstrap CI with:
  - cluster bootstrap by name key, or
  - permutation-inverted intervals
- Keep current strict eligibility gating unless calibration proves a better policy

## Failure modes and mitigations
- **Failure mode:** p-value direction still depends on observed sign.  
  **Mitigation:** explicit test object with fixed direction or absolute-value statistic.
- **Failure mode:** interval method ignores clustering.  
  **Mitigation:** cluster-aware resampling only.

## Acceptance criteria
- Position p-values are directionally valid.
- Intervals respect clustering.
- Report language calls this a position imbalance signal, not proof of manipulation.

## Implementation summary
- Replaced sign-adaptive one-sided permutation logic with a fixed two-sided absolute-effect test:
  - `permutation_test_id=position_rate_difference_permutation_abs_two_sided_v1`
  - `permutation_test_sidedness=two_sided_abs_effect`
  - `permutation_p_value_two_sided`
- Replaced naive rate-difference interval path with cluster bootstrap by name key:
  - `rate_difference_interval_method=position_rate_difference_cluster_bootstrap_v1`
  - `rate_difference_interval_draws` included in output.
- Updated position-family multiplicity/gating to consume the two-sided p-value field and compute significance from adjusted values.
- Updated duplicate position report language to "position imbalance signal" framing and two-sided permutation tooltip wording.
