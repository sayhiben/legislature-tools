# DUP-003 — Build versioned VRDB probability artifacts with geography-aware backoff and denominator variants

**Priority:** P0  
**Status:** Done (2026-02-28)  
**Depends on:** DUP-002

## Goal
Turn VRDB into a reusable probability source with explicit provenance, instead of an ad hoc file/query that is sampled differently in different parts of the stack.

## Scope
Produce versioned VRDB artifacts keyed by normalized names, including:
- statewide full-name frequencies
- county-conditioned full-name frequencies where denominators are reliable
- city-conditioned full-name frequencies only where field quality and denominator size support it
- optional first-name and last-name marginals for descriptive side panels

For each artifact row, store:
- `name_key`
- `count`
- `probability`
- `denominator`
- `geo_level`
- `geo_value`
- `baseline_variant`
- `vrdb_version`
- `normalization_version`

Also create denominator variants, at minimum:
- statewide all-registrants baseline
- statewide active-only baseline if policy/availability supports it
- geography-conditioned variants with explicit backoff metadata

## Backoff / shrinkage policy
Implement conservative geography backoff:
- city → county → statewide

Never pretend a city-conditioned estimate is precise if:
- the city field is sparse,
- city labels are messy,
- or the effective denominator is too small.

## Failure modes and mitigations
- **Failure mode:** city-conditioned tables become noisy and generate extreme expected values.  
  **Mitigation:** minimum denominator thresholds plus automatic backoff and explicit `effective_geo_level`.
- **Failure mode:** hearing geography fields are messy or inconsistent.  
  **Mitigation:** canonicalize geography inputs, emit quality flags, and back off when normalization confidence is low.
- **Failure mode:** analysts compare outputs across denominator variants without realizing they changed.  
  **Mitigation:** baseline variant and effective geography must be present in every output row and report label.

## Acceptance criteria
- Probability artifacts are versioned and reproducible.
- Every row records its effective geography level and denominator.
- Backoff behavior is deterministic and test-covered.
- Artifacts can be regenerated from source data with matching checksums/metadata.

## Verification
- Artifact build tests on known fixture subsets.
- Threshold tests for geography backoff.
- Rebuild reproducibility tests from the same VRDB snapshot.
