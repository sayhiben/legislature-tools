# DUP-002 — Build one shared, versioned normalization layer for submissions and VRDB

**Priority:** P0  
**Status:** Planned  
**Depends on:** DUP-001

## Goal
Ensure that every VRDB-derived expectation is computed on exactly the same normalized name representation used by the submission pipeline, duplicate counting, and report rendering.

## Why this is necessary
A VRDB collision null is only meaningful if the submission data and VRDB are normalized the same way. If the project uses one canonicalization path for hearing submissions and a slightly different one for VRDB ingest, the resulting probabilities and collision counts will not be comparable.

## Scope
Create a single versioned normalization module that produces, at minimum:
- `full_name_key`
- `first_name_key`
- `last_name_key`
- raw display/audit fields preserved alongside normalized fields

Normalization policy must explicitly define:
- case folding
- whitespace collapse
- punctuation / apostrophe / hyphen handling
- suffix handling
- `LAST, FIRST` reordering
- nickname lookup behavior only where explicitly allowed

## Important policy constraints
- The **primary VRDB collision baseline** must be built on normalized **full-name** keys.
- First-name-only and last-name-only metrics may be shown as descriptive side panels, not primary inferential drivers.
- No phonetic matching.
- No spelling-correction or edit-distance matching.
- Nickname expansion remains the only allowed “loose” matching path.

## Failure modes and mitigations
- **Failure mode:** engineers add a sidecar-only normalizer for VRDB.  
  **Mitigation:** require all call sites to use the same exported normalization function and version tag.
- **Failure mode:** normalization collapses distinct names too aggressively.  
  **Mitigation:** keep raw name strings in all audit tables and version every normalization change.
- **Failure mode:** report uses a different key than the inferential engine.  
  **Mitigation:** emit the active normalization version and active inferential key into all downstream tables.

## Acceptance criteria
- Submission ingest and VRDB artifact generation call the same normalization library.
- Every VRDB-derived output includes `normalization_version`.
- Raw and normalized name fields are both available for audit/debug workflows.
- Full-name key is the default driver for VRDB collision metrics.

## Verification
- Golden tests for canonicalization edge cases.
- Cross-source parity tests: the same raw name normalizes identically in submission and VRDB pipelines.
- Regression tests for nickname handling and for “no fuzzy matching beyond nickname lookup.”
