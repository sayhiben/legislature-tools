# DUP-019 — Treat `unmatched_only` inference as descriptive-only until a dedicated unmatched baseline exists

**Priority:** P2  
**Status:** Done (2026-03-01)

## Goal
Avoid spurious significance when the scope population is not represented by the baseline population.

## Problem
If a scope is explicitly “not matched to the voter registry,” then a voter-registry baseline is not a defensible inferential population for that scope.

## Scope
- For `unmatched_only` with registry-based baselines:
  - emit descriptive-only or unavailable status
  - suppress p/q/z and significance flags
- Add explicit report language explaining why
- Add future hook for a dedicated unmatched baseline if one is later developed

## Failure modes and mitigations
- **Failure mode:** unmatched-only appears extremely anomalous simply because the baseline excludes the relevant population.  
  **Mitigation:** disable inference until a proper baseline exists.
- **Failure mode:** analysts mistake descriptive-only summaries for inferential calls.  
  **Mitigation:** same descriptive-only badge/rules as DUP-008.

## Acceptance criteria
- No inferential outputs are produced for unmatched-only under registry baselines.
- Reports clearly state why unmatched-only is descriptive-only.
- Future dedicated-baseline extension path is documented.

## Verification
- Unit tests for unmatched-only mode guards.
- UI snapshot tests for descriptive-only labeling.
- Regression tests ensuring p-values stay suppressed.

## Implementation summary
- Added unmatched-scope inferential guardrail in `duplicates_exact`:
  - new inferential reason:
    - `unmatched_scope_registry_baseline_unsupported`
  - for `scope=unmatched_only` under registry baselines (`vrdb_full_histogram` / `vrdb_full_keys`), inferential status is forced to `descriptive_only`.
- Added explicit future-baseline hook point in detector logic:
  - `_scope_registry_baseline_inference_supported(...)` now centralizes whether unmatched scope can be inferentially tested.
  - current behavior is intentionally conservative until a dedicated unmatched baseline exists.
- Preserved inferential suppression contract across downstream outputs for unmatched scope:
  - no inferential p/q/z/significance outputs for unmatched-only rows when guard is active.
- Added report-language propagation:
  - methodology caveat now explicitly states unmatched-only is descriptive-only until a dedicated unmatched reference baseline exists.
  - duplicate declaration notes now include inferential reason text (not just status).
- Fixed two latent scope-indexing bugs discovered while exercising unmatched scope paths:
  - per-name family adjustment indexing
  - bucket family adjustment indexing
  - both now use explicit scope-local index lists, avoiding misaligned boolean-index loc errors for non-contiguous scope indexes.
