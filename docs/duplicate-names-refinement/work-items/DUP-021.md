# DUP-021 — Build a calibration harness and derive low-power thresholds from explicit operating targets

**Priority:** P2  
**Status:** Planned

## Goal
Replace heuristic low-power rules with thresholds justified by documented false-positive and power targets.

## Scope
Build a reproducible simulation and evaluation harness covering:
- clean null hearings
- homonym-heavy legitimate samples
- injected repeated-name scenarios
- same-position concentration
- temporal bursts
- varying match coverage and missingness
- normalization sensitivity
- geography-conditioned VRDB variants

Use it to set:
- `low_power_min_unique_names`
- `low_power_min_expected_duplicates`
- family-specific gating thresholds
- any shipping thresholds for new VRDB sidecar outputs

## Failure modes and mitigations
- **Failure mode:** thresholds are chosen by intuition and drift over time.  
  **Mitigation:** encode targets such as minimum detectable effect and FDR goals.
- **Failure mode:** evaluation only checks formulas, not operating characteristics.  
  **Mitigation:** require simulation-based calibration reports as release artifacts.

## Acceptance criteria
- Low-power thresholds are justified by an explicit target.
- Calibration outputs are reproducible and versioned.
- Changes to inference code can be regression-tested against statistical operating benchmarks.

## Verification
- CI smoke calibration suite.
- Periodic full calibration run.
- Release gate on key operating-characteristic regressions.
