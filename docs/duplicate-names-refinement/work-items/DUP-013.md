# DUP-013 — Repair temporal diagnostics with gating, multiplicity control, and a hearing-aware null

**Priority:** P1  
**Status:** Done (2026-02-28)

## Goal
Turn temporal burst outputs into controlled follow-up evidence rather than a large unadjusted source of false positives.

## Scope
- Only run inferential temporal tests for names that pass the per-name screen.
- Apply multiplicity control across names within each temporal family.
- Improve the null so it preserves:
  - hearing-wide submission intensity over time
  - optionally position or agenda-phase structure when available
- Downgrade to descriptive-only when the required null is not supportable

## Failure modes and mitigations
- **Failure mode:** every repeated name gets multiple temporal p-values.  
  **Mitigation:** gate by per-name screen and correct within-family.
- **Failure mode:** null ignores bursty site traffic or agenda-phase effects.  
  **Mitigation:** conditioned resampling or an intensity-based null.

## Acceptance criteria
- No temporal p-values are emitted outside the configured gate.
- Temporal outputs carry adjusted q-values or are descriptive-only.
- The null preserves hearing-wide time intensity by construction.

## Implementation summary
- Added temporal null configuration:
  - `name_analysis.temporal_null_mode` with:
    - `hearing_intensity`
    - `hearing_intensity_by_position`
- Temporal inferential p-values are now computed only for names that pass the per-name (Family C) inferential gate.
- Added position-conditioned temporal null support and explicit downgrade behavior when conditioning strata are unsupported:
  - `gate_reason=temporal_null_not_supportable`
  - `inferential_reason=temporal_null_not_supportable`

- Added temporal metadata fields to `temporal_burst_signals`:
  - `temporal_null_model`
  - `temporal_null_supported`
  - `temporal_null_support_reason`
