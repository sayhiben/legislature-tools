## 3. Observed Collision Metrics (Formal Notation)

  

Let:

- name groups indexed by `g`

- count in group `g`: `X_g`

- total rows `n = sum_g X_g`

- unique names `U = sum_g 1[X_g > 0]`

  

Observed collision metrics:

  

1. `pairs`

  

`pairs = sum_g C(X_g, 2) = sum_g X_g (X_g - 1) / 2`

  

2. `excess_rows`

  

`excess_rows = sum_g (X_g - 1)_+ = n - U`

  

3. `repeated_group_rows`

  

`repeated_group_rows = sum_g X_g * 1[X_g >= 2]`

  

Implementation source:

- `/Users/sayhiben/dev/legislature-tools/testifier_audit/src/testifier_audit/names/collision_baseline.py` (`collision_metrics_from_counts`)

  

### 3.1 Invariants and bounds used in tests

  

Validated invariants include:

- Expected metrics are zero for `n in {0,1}`.

- Bounds:

  - `pairs >= 0`

  - `0 <= excess_rows <= max(n-1,0)`

  - `0 <= repeated_group_rows <= n`

- Pair expectations scale with `C(n,2)` under fixed probabilities.

- `repeated_group_rows` is nonlinear in `n`.

- Hearing-observed-only baseline can inflate expected collision metrics relative to broader histogram baselines.

  

See tests:

- `/Users/sayhiben/dev/legislature-tools/testifier_audit/tests/test_collision_baseline_math.py`

  

## 4. Baseline Construction And Fallback Hierarchy

Configured via `collision_baseline_source`:

  

1. `hearing_empirical`

- Histogram built from observed per-name counts in current scope.

  

2. `vrdb_full_histogram`

- Pull pre-aggregated registry histogram (`name_count`, `n_keys`, `N`) from Postgres.

  

3. `vrdb_full_keys`

Registry fetches implemented in:

### 4.2 Failure policy: `fail` vs `degrade`

  

If registry baseline requested and unavailable (no DB URL, empty result, query error):

- `fail`: raises `RuntimeError`

- `degrade`: falls back to `hearing_empirical`, sets degraded flags

  

Degradation is surfaced in:

- `collision_methods.baseline_degraded`

- summary `baseline_degraded`

  

### 4.3 Population size `N_used`

  

`N_used` is the effective baseline population size used for expectation and tail models.

  

Sources:

- from histogram `N` (or recomputed `sum(name_count * n_keys)`)

- may be replaced by stratified population total when stratification is active/effective

- may be zero in degraded/unavailable scenarios, which pushes some inferential paths to conservative defaults.

  

### 4.4 Stratification: `birth_decade`

  

Only allowed stratifications: `none`, `birth_decade`.

  

For `birth_decade`:

- pulls `(name_key, stratum, n_registry_rows)` from registry.

- computes scope-specific stratum weights by proportional assignment of observed counts across a name's stratum distribution.

- builds mixture probability `P(name_key)` by weighted combination of stratum-specific name frequencies.

  

Degradation to `none` occurs when:

- baseline source is hearing empirical

- registry unavailable

- stratum frequencies empty/error

- derived mixture probabilities invalid/empty

  

Stratification status is recorded in:

- `collision_methods.stratification`

- `collision_stratification_sensitivity` (`requested` vs `effective`)

  

## 5. Expected Metric Mathematics

  

### 5.1 Histogram parameterization

  

Let histogram classes be indexed by `j`:

- `c_j`: count per name in class `j` (`name_count`)

- `h_j`: number of names in class `j` (`n_keys`)

- `N = sum_j c_j h_j`

- class-level key probability `p_j = c_j / N`

  

### 5.2 Multinomial baseline expectations

  

Assume draws with replacement from key-probability distribution.

  

Expected unique names:

`E[U] = sum_j h_j * (1 - (1 - p_j)^n)`

  

Expected singletons:

`E[S] = sum_j h_j * n p_j (1 - p_j)^(n-1)`

  

Expected metrics:

- `E[pairs] = C(n,2) * sum_j h_j p_j^2`

- `E[excess_rows] = n - E[U]`

- `E[repeated_group_rows] = n - E[S]`

  

### 5.3 Hypergeometric baseline expectations

  

Assume sample without replacement from finite population `N` with key multiplicities.

Constraint: `n <= N`.

  

For class `j` with multiplicity `c_j`:

- `P0_j = P(X=0) = C(N-c_j, n) / C(N,n)`

- `P1_j = P(X=1) = c_j * C(N-c_j, n-1) / C(N,n)`

  

Then:

- `E[U] = sum_j h_j * (1 - P0_j)`

- `E[S] = sum_j h_j * P1_j`

- `E[pairs] = C(n,2) * sum_j h_j * c_j(c_j-1) / (N(N-1))`

- `E[excess_rows] = n - E[U]`

- `E[repeated_group_rows] = n - E[S]`

  

### 5.4 Probability-derived expectation path

  

When direct probabilities are available (`expected_collision_metrics_from_probabilities`), multinomial formulas above are computed directly from normalized `p_i` over keys.

  

### 5.5 Hypergeometric stratified approximation from probabilities

  

For stratified + hypergeometric, implementation may build an approximate histogram from probabilities by:

- `expected_count_i = p_i * N_population`

- rounding to integers

- classing rounded counts into histogram bins

  

This introduces approximation error (discretization + class compression), especially in long tails.

  

### 5.6 Distinguishing expectation vs uncertainty

  

- Expected values come from analytic formulas (`expected_collision_metrics*`).

- Uncertainty bands (`p05`, `p50`, `p95`) and empirical p-values require Monte Carlo samples.

- If no samples exist, summary defaults to deterministic expected values with `z=0`, `p=1`.

  

## 6. Monte Carlo Methodology

  

### 6.1 Unstratified null simulation by histogram classes

  

Implemented in `simulate_collision_null_from_histogram(...)`.

  

For each draw:

1. Sample class allocations:

   - `M ~ Multinomial(n, q)`

   - `q_j = c_j h_j / N`

2. For each class `j`, distribute `M_j` rows across `h_j` names uniformly.

3. Compute `pairs`, `excess_rows`, `repeated_group_rows` from resulting occupancy.

  

### 6.2 Small-draw optimized cases

  

Within each class:

- `m <= 1`: no contribution.

- `m = 2`: analytic Bernoulli for collision probability `1/h`.

- `m = 3`: analytic triad mixture (`all same`, `one pair`, `all distinct`).

- `m >= 4`: explicit random assignment and occupancy counting.

  

### 6.3 Stratified Monte Carlo

  

Implemented in `_simulate_stratified_collision_null(...)`.

  

For each draw:

1. Sample rows across strata: `N_s ~ Multinomial(n, w_s)`.

2. Within each stratum, sample key ids by stratum-specific key probabilities.

3. Concatenate sampled key ids and compute occupancy-based metrics.

  

Used only for stratified + multinomial paths.

  

### 6.4 Draw-budget logic

  

#### `_collision_monte_carlo_draw_budget(n_rows, hard_cap)`

  

Let `requested = min(monte_carlo_draws, hard_cap)`.

  

Rules:

- if `requested <= 0` or `n <= 1`: `0`

- if `n <= 3`: `min(requested, 64)`

- else:

  - `scale = min(1.0, max(0.20, sqrt(n/400)))`

  - `budget = round(requested * scale)`

  - return `min(requested, max(48, budget))`

  

#### `_bucket_monte_carlo_draw_budget(n_rows, expected_primary_metric, hard_cap)`

  

Returns `0` if guaranteed low-power by thresholds:

- `n_rows < low_power_min_unique_names`, or

- `expected_primary_metric < low_power_min_expected_duplicates`

  

Else delegates to scope budget function.

  

Current hard caps in detector:

- scope-level: `hard_cap=1000`

- bucket-level: `hard_cap=250`

  

### 6.5 When Monte Carlo is skipped

  

- `collision_uncertainty_mode = analytic_only`

- hypergeometric simulation path in `simulate_collision_null_from_histogram` (returns empty)

- draw budget computed as zero

- low-power-gated bucket simulation

  

### 6.6 Derived statistics from samples

  

For each metric with non-empty samples:

- `expected_p05`, `expected_p50`, `expected_p95`: sample quantiles

- `z_score`: `(observed - sample_mean) / sample_sd` (`ddof=1`)

- `p_value`: one-sided empirical upper-tail

  - `(count(null >= observed) + 1) / (n_draws + 1)`

  

Important directionality point:

- empirical p-values only quantify over-concentration (upper tail).

- under-concentration is reflected in signed deviation/z-score, not two-sided empirical p.

  

## 7. Per-Name Inferential Pipeline

  

### 7.1 Per-name expected counts and probabilities

  

Within each scope, names are grouped to get `observed_count_i`.

  

Population inputs per name:

- stratified mode: `population_probability_i` from mixture; `population_count_i = p_i * N_used`

- non-stratified registry mode: `population_count_i` from registry fetch

- hearing empirical mode: `population_count_i = observed_count_i`

  

Then:

- `population_probability_i = population_count_i / max(N_used, 1)`

- `expected_count_i = population_probability_i * n_scope`

  

### 7.2 Tail models

  

Configured by `per_name_significance_model`:

- `binomial_tail`:

  - `p_i = P(Bin(n_scope, population_probability_i) >= observed_count_i)`

- `hypergeometric_tail`:

  - `p_i = P(Hypergeom(N_used, population_count_i, n_scope) >= observed_count_i)`

  

Both are one-sided upper tails.

  

### 7.3 Multiple testing

  

BH-FDR is applied within each scope to per-name p-values:

- `q_i = BH(p_i)`

- significant if `q_i <= bh_fdr_q`

  

### 7.4 Display censoring vs tested totals

  

- `per_name_tests`: full tested set (no display truncation).

- `per_name_display`: top `per_name_display_limit` rows.

- `display_truncated` indicates whether display subset is truncated.

- `summary.n_significant_per_name` is computed from full grouped tests, not display subset.

  

## 8. Position And Temporal Sub-Methods

  

### 8.1 Position interval method

  

Method id:

- `position_duplicate_interval_multinomial_mc_v1`

  

For each position subset with `n_rows = n_pos`:

- expected duplicate rows computed analytically from baseline histogram.

- if baseline model is multinomial, Monte Carlo draws generate interval quantiles.

- row-rate intervals are row-intervals divided by `n_pos`.

  

Eligibility gating (`_position_claim_status`):

- ineligible if baseline model not multinomial

- ineligible if no rows

- ineligible if any position is low-power

- ineligible if interval draws unavailable

  

### 8.2 Position permutation test (Pro vs Con)

  

`_position_permutation_test(...)` does:

1. Compute observed duplicate-row rates for Pro and Con.

2. Permute row indices while preserving Pro and Con totals.

3. Recompute rate difference per permutation.

4. One-sided p-value chosen by observed sign.

5. Bootstrap CI for difference via binomial resampling (`n_boot=4000`).

  

Output includes:

- rate difference, CI, rate ratio, one-sided permutation p.

  

### 8.3 Temporal permutation diagnostics

  

`_temporal_metrics_by_name(...)`:

- For each name with >=2 timestamps:

  - observed stats: minimum gap, pair counts <=5m and <=15m, time span.

- Null generation:

  - sample `sample_size` timestamps without replacement from all hearing minutes.

  - repeats up to `min(temporal_permutation_draws, 1000)`.

- p-values:

  - min-gap p: lower-tail (`null <= observed`)

  - within-5m and within-15m p: upper-tail (`null >= observed`)

  

No BH correction is applied across names for these temporal p-values.

  

## 9. Report-Layer Baseline Reinterpretation

  

### 9.1 Key separation: detector vs report expectations

  

Detector table `collision_by_bucket` contains metric-specific expected values from collision baseline mathematics.

  

Report chart `duplicates_exact_bucket_concentration` is rebuilt in payload code and uses different expectations:

- unit options: `rows_anywhere`, `names_anywhere`

- expected values are volume-share expectations, not direct detector metric expectations.

  

### 9.2 Payload reconstruction logic

  

In `/report/rendering/payload/builder.py`, chart rows are assembled by:

  

1. Building bucket skeleton from `collision_by_bucket` primary metric rows.

2. Expanding by scope + match mode combinations from per-name mode tables.

3. Computing observed unit counts from timing table:

   - `unit_observed_rows`: row count of duplicated-anywhere names in bucket

   - `unit_observed_names`: distinct duplicated-anywhere names in bucket

4. Computing global duplicated totals per scope/mode from per-name mode tables.

5. Defining total rows in scope from methods `n_used` (or fallbacks).

6. Computing expected unit counts:

   - `unit_expected_rows = bucket_n_rows * global_duplicated_rows / total_rows_in_scope`

   - `unit_expected_names = bucket_n_rows * global_duplicated_names / total_rows_in_scope`

7. Emitting signed deviations and presenting two metrics:

   - rows_anywhere

   - names_anywhere

  

### 9.3 Control filtering behavior in frontend

  

In `/report/static/report/main.js`:

- bucket-concentration chart filtering order:

  1. scope

  2. match mode

  3. metric unit (`rows_anywhere` or `names_anywhere`)

- diagnostics chart filtered by scope.

- top-name timing and per-name charts filtered by scope + match mode.

  

### 9.4 Interpretation consequence

  

The report's displayed `expected_duplicate_rows` for concentration charts is not the same statistical object as detector collision expected metrics in `collision_by_bucket`.

  

This is intentional in current implementation, but reviewers should treat these as distinct baselines:

- detector-level collision null expectation

- report-level volume-share concentration expectation

## 11. Critical Appraisal For Statistician Feedback

  

### 11.1 Strengths

  

1. Metric definitions are explicit and mathematically coherent across analytic and simulated paths.

2. Baseline provenance and degradation are surfaced in machine-readable tables.

3. Scope-aware stratification framework exists and records requested vs effective stratification.

4. Low-power rules are explicit and test-covered.

5. Deterministic seeding enables reproducibility at fixed code/config/order.

  

### 11.2 Limitations and ambiguity points

  

1. One-sided emphasis:

- Collision empirical p-values and per-name tests are upper-tail only.

- Under-concentration is not symmetrically inferentially calibrated.

  

2. Multiple-testing scope inconsistency:

- BH is applied for per-name tests only.

- Collision-metric p-values, bucket p-values, and temporal p-values are not globally FDR-controlled.

  

3. Hypergeometric uncertainty gap:

- No hypergeometric Monte Carlo simulation in collision null sampler.

- Hypergeometric paths rely on analytic expectations with no simulation quantiles.

  

4. Stratified hypergeometric approximation:

- Probability-to-histogram rounding can distort tails and occupancy behavior.

  

5. Low-power thresholds are heuristic constants:

- `low_power_min_unique_names` and `low_power_min_expected_duplicates` are fixed cutoffs, not calibrated by objective error-control targets.

  

6. Detector/report baseline mismatch risk:

- UI concentration expectations are volume-share reconstructions, distinct from detector null expectations.

- Users may conflate these unless explicitly warned.

  

7. Scope fallback semantics when match assignments unavailable:

- `matched_only` may degenerate to full-hearing copy, potentially misleading scope interpretation.

  

### 11.3 Targeted statistician review checklist

  

1. Tail directionality

- Should collision and per-name inference remain one-sided upper-tail, or should two-sided calibration be adopted for symmetry?

  

2. Multiple testing scope

- What family definitions should govern FDR control (per-name only, per-scope multi-family, all detector hypotheses)?

  

3. Stratified hypergeometric approximation

- Is probability-rounding-to-histogram acceptable, or should finite-population stratified sampling be implemented directly?

  

4. Low-power gates

- Are current thresholds (`min unique names`, `min expected duplicates`) defensible, or should they be derived from target Type I/II operating characteristics?

  

5. Empirical p-value form

- Is one-sided empirical `P(null >= observed)` appropriate for collision metrics, and should tail selection be metric-specific or effect-direction aware?

  

6. Detector-vs-report expectation separation

- Should report concentration charts continue using volume-share expected counts, or should detector-native expected metrics be exposed as primary expectations to reduce conceptual mismatch?

  

7. RNG stream dependence

- Given one shared RNG across multiple stochastic components, should independent seeded streams per sub-method be used to reduce order-sensitivity in reproducibility?

  

8. Position inference eligibility

- Is requiring all positions to be non-low-power for global position claim eligibility too strict, or should eligibility be position-specific?

  

9. Temporal permutation multiplicity

- Should temporal per-name p-values receive BH or hierarchical correction before interpretation?

  

10. Scope fallback when assignments absent

- Should `matched_only`/`unmatched_only` be disabled (explicitly unavailable) instead of auto-fallback to avoid semantic drift?
